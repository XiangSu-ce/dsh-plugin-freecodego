<a id="settings-surface"></a>
## 设置表面

FreeCodeGo 设置分区报告引擎代、已持久化的默认引擎状态、后端可用性与本地第三方提供方路由。提供方摘要读取自标准的 `llm.providers` Host API，并在每次连接代重置后刷新。

路由的创建与编辑刻意留在共享的 Models 设置表面（`@deepseek-ai/dsh-client-ui-settings-models`）。该编辑器通过 `settings.mutate` 写入 `llm-pi-ai` profile，通过 `credentials.set` 写入 API key；浏览器永远拿不到已存储的密钥值。FreeCodeGo 不新增并行凭据协议。

在公开后端契约可用之前，FreeCodeGo Cloud 控件显示为 `BACKEND_NOT_CONFIGURED`。

设置页还公开独立的 WorkBuddy 设备登录流程。它打开 WorkBuddy 的浏览器授权 URL，在用户确认后轮询，并且只显示 UID、昵称、登录状态与动态 CLI 模型 id。可以独立添加和移除多个账号；令牌留在 Host 凭据服务中，绝不发送给浏览器。

同一设置表面还包含一张 Agnes AI 卡片，用于验证码注册、登录与自动创建默认 API key。Agnes 凭据由 Host 凭据服务存储；浏览器永远拿不到会话令牌或 API key。

启用 Engineering 时，该页面还公开一个多引擎团队面板。它在启动隔离的 DeepSeek、Codex 与 Claude 子评审时保持所选 root Agent 不变，并为每个有界议会议题显示法定人数、失败项、共识与异议。完成的报告提供明确的 Approve implementation 与 Reject plan 操作。只有批准之后才会显示实施后验证操作及其已持久化的阶段结果。

<a id="model-menu-and-provider-cards"></a>
## 模型菜单与供应商卡片

聊天里的模型列表是 Harness 原生菜单，而 Host 会把所有可服务的适配器都注册进去。有四块客户端机制在不替换它的前提下塑造它：

- **选择器显示什么**由账号与供应商页面按供应商或按模型决定。存储是反向的（除非记录为隐藏，否则可见），并带两条声明的例外 —— 按量计费供应商的有价行与精选供应商的未命名行默认隐藏 —— 所以从没打开过这些开关的用户不会看到变化，而新增的**有价**模型不会自己打开。装饰层在渲染一个供应商分组或一行之前先读这份存储，所以决定会作用于旁边已经打开的那份菜单。
- **只给行加标注，不重建行。** `native-model-menu-badges` 对符合稳定 ARIA 菜单契约的行追加非交互的来源、价格类别与健康标签；官方选择器仍然是选择、焦点、滚动与推理档位的所有者。
- **选择器标签回显会话选择。** `model-selection-echo` 检查目录发布出来的**结果**，而不只是监听异常，因为被拒绝的 `selectModel` 是以 Remote 失败的形式 resolve 的 —— 把它当成已应用的选择会清掉它刚写下的原因。
- **重连不会清空菜单。** `model-catalog-retry` 识别传输性失败，并按 1 分钟 / 10 分钟 / 30 分钟退避重新加载，且不清空上一次可用的目录。

每个供应商对应一张卡片（`provider-card.tsx`），而不是各写一套区块：身份与状态、当下实际提供的模型云、然后是由调用方提供的控件。此前四个供应商漂成了四种布局，其中两个还手写了一组与实时目录矛盾的名单。

<a id="code-review-panel"></a>
## 代码审查面板

`设置` 页上带着代码审查面板（`ReviewPanel`）：模式（`off` / `record` / `gate`）、严重级阈值、以回合计的冷却、深度审查与对抗复核，以及一个发起按需运行的按钮。这个 remote 是发起即返回的 —— 一次运行按文件花模型调用、可能跑上几分钟 —— 所以面板只启动运行，随后轮询同一个 remote 获取状态，显示排队中的运行，并连同覆盖面算术一起展示报告。每个审查 remote 都接收会话 id 并据此解析工作目录，因此面板无法询问一个会话从未打开过的检出目录。

<a id="usage-media-and-session-overlays"></a>
## 用量、媒体与会话浮层

- **Token 用量面板** —— 本地账本与脱敏后的用量视图，使用共享的堆叠条形视觉呈现。
- **生成媒体** —— 图片、视频与音频工具调用有各自的工具视图，而工具读取的媒体默认值就在这个设置表面里。
- **语音输入** —— 输入框上的控件，经 Groq Whisper 路由转写（`voiceInputEnabled`）。
- **方案复核** —— 读回当前方案并带行号，按行收集意见，再合成一条返工消息（行号与 Host 自己的打印一致，所以意见不会落到另一行上）。
- **会话删除** —— 当日志已经不存在时幂等地清掉侧边栏那一行；而仍活着的会话必须先关闭。
- **护栏、沙箱与信任** —— Host 为界面镜像的那些护栏开关（凭据路径与环境读取护栏、原生引擎的死循环护栏、LSP 自动挂载、压缩后补灌）、当前会话的沙箱模式（并读回实际生效的模式），以及文件夹信任的授予/撤销控件与它所门控的项目配置报告。
- **自动化** —— 声明式的失败恢复链（含深度护栏与冷却），以及日历规划器的总开关。
- **上下文开关** —— Headroom 压缩与延迟工具 schema 各自有面板与其实时计数，因此一项会改变模型所见内容的开关，与它节省的量一起可见。
- **社区插件与能力市场** —— 有界、分页的元数据；只有当已发布的详情可以在没有未解析的环境变量或 header 值的情况下被表达时，才提供一键安装，任何需要凭据的项都留在手动配置里。共享的 README 读取器会先试惯用的中文 README 名再退回英文，并报告它实际读了哪个文件，因此英文回退会被标明，而不是被冒充成本地化内容。

<a id="mcp-and-skills"></a>
## MCP 与 Skills

`设置` 页面持有 MCP 与 Skill 开关。开关会注册对应的 `MCP` 或 `Skills` 设置侧栏入口，因此未启用的能力不会带来休眠的导航项。MCP 页面显示连接状态、已发现的工具、启用状态、编辑与快捷模板；Skills 页面把已配置的根与已发现的 catalog 分开呈现。配置只通过 FreeCodeGo Host remote 发送，并从一份共享清单应用到新的 DeepSeek、Claude 与 Codex 会话。

<a id="plugin-conflict-protection"></a>
## 插件冲突保护

`设置` 页面公开默认开启的「插件冲突保护」开关与最近五次自动修复。它说明修复会保留较早加载的活动插件，并在较晚的冲突条目启动之前将其禁用。当观察到新的修复时，一个覆盖整个 frame 的模态框会点名被保留的插件、被禁用的插件与重复的资源。

<a id="embedded-community-plugins"></a>
## 内嵌社区插件

FreeCodeGo 设置页包含一个精选的社区插件页面。它消费本地 `dsh-market` Host 路由（`/dsh-market/registry`、`/dsh-market/install`、`/dsh-market/status` 与 `/dsh-market/restart`），而不是实现第二套包安装器。部署方应当把较新的 `dshmarket` bundle 与 `embedded` client 行为组合在一起；该市场的完整导航被抑制，其经校验的安装引擎仍可供 FreeCodeGo 页面使用。

社区包含 `插件` / `MCP` / `Skills` 过滤器。MCP 页面读取分页的 MCP.so 目录与实时分类计数；Skills 页面读取分页的 skills.sh 目录。两者都保留由 Host 持有的搜索与安装，因此浏览器代码拿到目录元数据，但绝不执行市场安装命令。

社区过滤器旁边固定的 `已安装插件` 入口会打开已安装社区插件列表。卡片显示其激活状态，并把安装操作替换为 `卸载`。该请求由 Host 接收，因此它可以停用正在运行的 Loader 条目，并把包操作交给 `dsh plugin`——profile 包清单由它一人维护；浏览器代码不运行 `pnpm`，也不改动 profile 文件。

<a id="companion-in-the-sidebar-rail"></a>
## 侧边栏、输入框上方与对话中的形象

选中会话自身的活动会以一个形象呈现，分坐三处且始终一致。侧边栏标记注册进上游的 `sidebar.brand.mark` 槽位，优先级比默认占用者低一级，因此官方标记与其周围的所有控件——收起按钮、品牌行的新建会话入口——仍属于上游。输入框上方的条带则挂进 `conversation.input.dock`，排在上游的 todo、goal、queue 三条之后，并与那两条一样骑在对话自己的内容轴上：居中、按共享的输入框 token 裁到输入卡宽度，再用侧边间隙把它内缩回来，让标记与正文对齐。它测量自己的内容盒，因此对话变宽时画出的形象会跟着变大，而不是维持同一个小点。dock 本身是全宽的，而停在那个全宽上的条带——也就是它原来的样子——会从对话列的外缘开始，比它描述的那张卡片往外一百多像素，并且给形象按一个读者根本没在看的更宽列来算尺寸。在「空白会话」的新建对话页上它什么都不画——那一页还没有任何回合可描述，而一条「是谁都没让它做的活」的状态行不该是空输入框上方第一眼看到的东西——第一次发送时由框架自己的 `session.blank` 位把它落座。第三处不是注册而是注入：对话区里「本轮运行中」那一行状态属于上游，它没有提供槽位，因此形象直接接管这一行——保留它的盒子、它在列中的位置、它的 role 语义、给读屏器的文案，以及它的已用时长，只把闪烁的加载动效换成另外两处已经决定的形态。同一时刻只画一个形象：已挂载的运行行在它存在期间拥有绘制权，输入框上方的条带就在这段时间里让出绘制——但保留自己那条高度与文案，因此这次交接不会推动任何东西。另外两处是同一类注入，落在本体另外两种加载动效上。回合进行中，本体会给每一行「还在跑」的行画一条扫光——同一套手法它写了五遍（命令行、推理、工具三种画在行元素上，skill 行自己手写一遍，bash 行画在自己的盒子上），所以这里不去枚举这些写法，而是问「这一行里哪个元素画了一个带动画的 `::after`」，把那条扫光关掉，再让形象站在该行最前面：24px 的行里放 18px，因此它挤不大自己插进去的那一行。而当本体的「进行中」标记是那颗圆点时——八格像素追逐，插件管理页的行里是 8px，其他都是 10px——形象就顶掉那颗圆点的位置：同一个槽位，圆点自己的 class 一并带过去，调用方的排版不动，而圆点本身只是关掉而不是删掉，因为它仍归 React 所有，React 把它移除正是形象被收回的时机。这一处只为「对话」说话：对话流、输入框区域、会话头部的动作区里的圆点会被顶掉，而设置页面里「某个包正在加载」的圆点保持本体原样——形象是 Agent 的标记，插件在安装并不等于 Agent 在工作。每行、每处标记都只画一个形象，绝不在同一处画两个。所有席位都从同一批 store 读同一批事实、跑同一个仲裁器，因此不可能对「Agent 正在做什么」给出不同答案。

形象显示当前会话在做什么——待机、开始、思考、输出中、执行工具、等待你的回答、出错、完成、有新消息、舒展、已休眠——并且每个形态都带有来自 `freecodego.companion` locale 命名空间的自有文案，因此「发生了什么」从不只靠一个形状来说。从那次首发送起，条带在会话的其余时间里保持同一条高度并始终挂载，因此它显示的任何内容都不会推动输入框及其上方的对话区；两种静息形态改为在同一行上绘制静息圆，而不是离开；且包括静息在内的所有形态都以足色绘制，因此待机时的清晰度与运行中一致。每个形态都会走完它自己动画量出的最短停留时长，因此一串连续的工具调用不会让画面闪烁；`prefers-reduced-motion` 下则冻结为单帧，而不是加快播放。

*回合内部的阶段*读自会话自己的事件日志，见 [`src/client/companion/activity.ts`](src/client/companion/activity.ts)：每条插件只建一份实时流，所有席位共用，因为会话列表只能报告「回合在跑」，分不出模型在思考、回复在写、还是在执行工具——而这正是这些形态存在的理由。进行中的工具调用、正在到达的回复、刚开始的回合、以失败结束的回合，以及从回合之外注入的消息（cron 提醒、文件变更通知、子代理结果），各自对应一个形态；其中涉及「某一瞬间」的三个，以承载它们的那条事件的持久身份发布，再由 [`src/client/companion/signals.ts`](src/client/companion/signals.ts) 的新闻窗口变成有界信号，因此失败留在日志里而形态不会比新闻活得更久。它们全部排在 `thinking` 之上——`thinking` 在一个回合的每个阶段都为真，所以排在它下面的档位，在一个回合的时长里根本没有读者能观察到。干活优先于模型自己的阶段，而「有人在等」优先于一切。

静息会话并不是静止的。在两个安静形态之间，形象会借用引擎目录里剩下的形态（`egg`、`wink`、`wide`、`hexagon`）舒展一下：每个安静周期一个形态，然后回到静息；只有会话安静到足够久之后才会关机进入 `sleep`。在会话等待下一条提示的这段时间里，一个从不动的标记看起来是坏了，而不是安静；关机形态是这场舒展的终点而不是与它竞争的档位，所以一个被独自放着的会话会先舒展几次，然后睡去。这个周期短到足以让整套目录在「一段安静的时长」里播完，因此其中没有哪个形态是永远摸不到的；而具体画的是哪一个，读自共享时钟，而不是各席位自己维护的计数——所以几处席位是在同一瞬间舒展、画同一个形态，而不是各自从自己挂载的时刻起走各自的目录。席位自身的安静时长只决定它是否已经休息够了、可以开始舒展。

该形象来自一份以 MIT 许可内嵌的引擎，按时间纯函数采样；内嵌副本的来源、哈希与许可记录在 [`src/client/companion/engine/PROVENANCE.md`](src/client/companion/engine/PROVENANCE.md)。

<a id="model-experience"></a>
## Model Experience

无，因为浏览器设置表面不注册任何工具、提示词分区或会话事件；它展示的路由与凭据由 Host 服务拥有。

#### KV Cache 影响

浏览器端渲染绝不进入请求，因此不会改变已缓存的 prefix。

## 已知限制与延期工作
<a id="known-limitations-and-deferred-work"></a>

- **设置页只做报告，不拥有实现** —— 引擎代号、持久默认状态与提供方路由都读取标准的 `llm.providers` Host API。
- **路由编辑留在共享的 Models 表面** —— FreeCodeGo 不新增第二个编辑器。
- **浏览器永远拿不到已存储的 key 值** —— 不存在并行的凭据协议。
- **Engineering 面板依赖插件自身的设置** —— Engineering 关闭时，多引擎团队面板是缺席而不是失效。
